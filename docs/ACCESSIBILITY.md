# Accessibility notes

Biography, five featured projects, five animated additional projects, experience, education, personal interests, toolkit, process descriptions, and contact links are native README text. Artwork reinforces meaning without being the only source of a fact.

- Native headings and descriptive anchors provide a reading path. All ten project summaries and the Beyond projects section are visible. Education, Professional certificates, and Outside work have native headings rather than a hidden disclosure.
- All thirteen active visual families have meaningful image alt text, desktop/mobile compositions, and complete static PNG counterparts. Nearby text carries project facts and process stages.
- The applied-AI process repeats stakeholder engagement, shared success criteria, and iterative feedback in native text and static content. Its meaning must not depend on following animated arrows or reading the footer alone.
- GIF sources are selected only when `prefers-reduced-motion: no-preference` matches. Reduced-motion users receive a desktop/mobile PNG; clients without suitable media-query support receive the default still.
- The hero, ten project panels, applied-AI process, and research process have four variants each: **52 active assets: 26 GIFs and 26 PNGs**. Motion does not carry unique factual content.
- Warm white and pale accents on navy support readable labels. Use short labels, generous spacing, and visual inspection at desktop and narrow widths when revising artwork.
- GitHub supplies page typography, focus indicators, and theme behaviour. Tables may scroll horizontally on narrow screens. No custom page JavaScript or CSS is required.
- GIFs have no inline pause controls in a README. Preserve static defaults and reduced-motion sources rather than using unconditional animated images.

The archived leaf artwork, retained SVGs, and other historical alternatives are not displayed in the current README. The reading path links to projects, the website, résumé, and contact channels; generation scripts and historical mesh exports belong in documentation.

A local HTML preview approximates GitHub rendering rather than guaranteeing identical behaviour across clients. This is accessibility-oriented design, not formal conformance certification. Report a barrier by [emailing Kun Ming](mailto:kunmingaden@gmail.com).
